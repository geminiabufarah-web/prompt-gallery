# البنية التقنية للمشروع

## 1. نظرة عامة على البنية

```
[ المستخدم (متصفح) ]
        |
        v
[ الواجهة الأمامية - React + Vite ]
   يُستضاف مجانًا على Vercel أو Netlify
        |
        |--- طلبات بيانات نصية (برومبتات، وسوم، مجموعات) ---> [ Supabase: قاعدة بيانات Postgres + Auth ]
        |
        |--- رفع/جلب ملفات الصور ---> [ Cloudflare R2: تخزين الصور فقط ]
```

**القاعدة الأساسية التي يجب الالتزام بها:** لا تُخزَّن أي صورة (Binary) داخل قاعدة بيانات Supabase أبدًا. قاعدة البيانات تخزّن فقط **مسار/رابط** الصورة في R2، والصورة الفعلية تبقى في R2.

---

## 2. التقنيات المطلوب استخدامها

| الطبقة | التقنية | ملاحظات |
|---|---|---|
| الواجهة الأمامية | React (مع Vite) | يمكن استخدام Next.js بدلاً منها إذا كان المطوّر يفضّلها، بشرط بقاء كل شيء ضمن الخطط المجانية |
| التنسيق (Styling) | Tailwind CSS | اختياري، لكن يُسرّع التطوير |
| قاعدة البيانات | Supabase (Postgres) | خطة Free — تكفي تمامًا لأنها نصوص فقط |
| المصادقة (تسجيل الدخول) | Supabase Auth | بريد إلكتروني + كلمة مرور، مستخدم واحد يُنشأ يدويًا |
| تخزين الصور | Cloudflare R2 | خطة Free — 10GB تخزين، بدون رسوم تحميل (Egress) |
| الاستضافة | Vercel أو Netlify | خطة Free |
| مكتبة مقارنة النصوص (Diff) | `diff` أو `jsdiff` (npm package) | لميزة مقارنة نسخ البرومبت |

## 3. آلية التعامل مع رفع وعرض الصور (مهم جدًا — يُرجى القراءة بعناية)

### عند رفع صورة جديدة:
1. المستخدم يختار صورة من الواجهة
2. الصورة تُرفع مباشرة إلى Cloudflare R2 (باستخدام R2 API المتوافق مع S3، أو عبر Presigned URL يُولَّد من طرف الخادم/Serverless Function)
3. يُنشأ أيضًا نسخة مصغّرة (Thumbnail) من الصورة لتسريع عرض المعرض الرئيسي (يمكن توليدها في المتصفح قبل الرفع، أو عبر معالجة بسيطة بعد الرفع)
4. بعد نجاح الرفع، يُحفظ في Supabase فقط: مسار الصورة الأصلية في R2 + مسار الصورة المصغّرة + بقية بيانات الإدخال (البرومبت، الوسوم، إلخ)

### عند عرض الصور:
- يجب أن تكون الصور قابلة للوصول عبر رابط عام (Public URL) من R2، أو عبر Presigned URLs مؤقتة إن أراد المطوّر حماية إضافية
- **الخيار الأبسط الموصى به:** ربط نطاق فرعي (Custom Domain) مجاني بحاوية R2 (Cloudflare يدعم هذا مجانًا) لجعل روابط الصور مباشرة وسريعة

### تنظيم مسارات الملفات داخل R2 (Naming Convention مطلوب الالتزام به):
```
{user_id}/{entry_id}/original.{ext}
{user_id}/{entry_id}/thumbnail.webp
```
هذا التنظيم يسهّل لاحقًا حذف كل ملفات إدخال معيّن دفعة واحدة عند حذفه.

## 4. الأمان
- كل طلبات قاعدة البيانات يجب أن تمر عبر Row Level Security (RLS) في Supabase، بحيث لا يمكن لأي طلب الوصول للبيانات إلا بعد تسجيل الدخول
- مفاتيح الوصول لـ R2 (Access Key / Secret Key) يجب ألا تظهر أبدًا في كود الواجهة الأمامية (Frontend) — يجب أن تُستخدم فقط داخل Serverless Function أو Edge Function آمنة، أو عبر Presigned URLs محدودة الصلاحية

## 5. البيئة المحلية (Development)
يجب أن يوثّق المطوّر خطوات تشغيل المشروع محليًا (على جهاز المطوّر) قبل التسليم، شاملة:
- كيفية تثبيت الحزم (`npm install`)
- ملف `.env.example` يوضح أسماء المتغيرات البيئية المطلوبة (بدون القيم الفعلية)
- أمر تشغيل المشروع محليًا (`npm run dev`)
