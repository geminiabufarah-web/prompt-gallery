# مخطط قاعدة البيانات (Database Schema)

قاعدة بيانات Postgres عبر Supabase. المستخدم واحد فقط حاليًا، لكن نضيف `user_id` في كل جدول لضمان إمكانية التوسعة مستقبلًا وتفعيل Row Level Security بسهولة.

---

## جدول `collections` (المجموعات/المشاريع)

| العمود | النوع | ملاحظات |
|---|---|---|
| id | uuid | Primary Key، افتراضي `gen_random_uuid()` |
| user_id | uuid | مرتبط بـ `auth.users` |
| name | text | اسم المجموعة، إلزامي |
| description | text | اختياري |
| created_at | timestamptz | افتراضي `now()` |

---

## جدول `tags` (الوسوم)

| العمود | النوع | ملاحظات |
|---|---|---|
| id | uuid | Primary Key |
| user_id | uuid | مرتبط بـ `auth.users` |
| name | text | اسم الوسم، **يجب أن يكون فريدًا لكل مستخدم** (Unique constraint على `user_id + name`) |
| created_at | timestamptz | افتراضي `now()` |

---

## جدول `entries` (الإدخالات — الجدول الرئيسي)

| العمود | النوع | ملاحظات |
|---|---|---|
| id | uuid | Primary Key |
| user_id | uuid | مرتبط بـ `auth.users` |
| collection_id | uuid | Foreign Key → `collections.id`، **يقبل NULL** (إدخال بدون مجموعة) |
| parent_entry_id | uuid | Foreign Key → `entries.id`، **يقبل NULL** — يُستخدم لربط النسخ/التعديلات (انظر ميزة 4.4 في PRD) |
| image_path | text | مسار الصورة الأصلية داخل R2، إلزامي |
| thumbnail_path | text | مسار الصورة المصغّرة داخل R2، إلزامي |
| prompt_positive | text | البرومبت الإيجابي، إلزامي |
| prompt_negative | text | البرومبت السلبي، اختياري |
| model_name | text | اسم النموذج المستخدم، اختياري |
| seed | text | اختياري (نص وليس رقم، لأن بعض النماذج تستخدم قيمًا غير رقمية) |
| steps | integer | اختياري |
| cfg_scale | numeric | اختياري |
| sampler | text | اختياري |
| extra_params | jsonb | لأي إعدادات إضافية غير مغطاة بالأعمدة أعلاه (مرن للتوسعة المستقبلية) |
| notes | text | ملاحظات شخصية، اختياري |
| is_favorite | boolean | افتراضي `false` |
| rating | integer | تقييم اختياري من 1 إلى 5، يقبل NULL |
| created_at | timestamptz | افتراضي `now()` |
| updated_at | timestamptz | يُحدَّث تلقائيًا عند أي تعديل |

**ملاحظة مهمة حول `parent_entry_id`:** هذا يكوّن علاقة ذاتية (Self-referencing) داخل نفس الجدول. عند جلب "شجرة النسخ" لإدخال معيّن، يجب البحث عن:
- الإدخال الذي هذا الإدخال هو نسخة منه (`parent_entry_id`)
- كل الإدخالات التي `parent_entry_id` الخاصة بها تساوي id هذا الإدخال (الأبناء)

---

## جدول `entry_tags` (جدول ربط — Many-to-Many)

يربط بين `entries` و `tags` لأن إدخالاً واحدًا قد يحمل عدة وسوم، والوسم الواحد قد يُستخدم في عدة إدخالات.

| العمود | النوع | ملاحظات |
|---|---|---|
| entry_id | uuid | Foreign Key → `entries.id` |
| tag_id | uuid | Foreign Key → `tags.id` |

Primary Key مركّب: `(entry_id, tag_id)`

---

## ملخص العلاقات (Relations)

```
collections (1) ────< (many) entries
entries (1) ────< (many) entries          [self-relation عبر parent_entry_id]
entries (many) ──── (many) tags            [عبر جدول entry_tags]
```

## فهارس (Indexes) موصى بإنشائها لتسريع البحث
- فهرس على `entries.prompt_positive` باستخدام Full Text Search في Postgres (لتسريع البحث النصي)
- فهرس على `entries.collection_id`
- فهرس على `entries.parent_entry_id`
- فهرس على `entries.is_favorite`

## Row Level Security (RLS) — إلزامي
يجب تفعيل RLS على كل الجداول أعلاه، بحيث لا يستطيع أي طلب قراءة أو تعديل صفوف لا تخصّ `auth.uid()` الحالي. هذا شرط أساسي قبل النشر على السيرفر العام.
