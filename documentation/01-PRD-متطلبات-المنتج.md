# متطلبات المنتج (PRD) — تطبيق مكتبة البرومبتات والصور

## 1. المشكلة التي يحلها التطبيق
المستخدم يولّد صورًا بواسطة أدوات ذكاء اصطناعي (Midjourney, Stable Diffusion, DALL-E، إلخ)، ويحفظ كل صورة والبرومبت النصي الخاص بها يدويًا على جهازه. مع تراكم عشرات/مئات البرومبتات — وكثير منها نسخ معدّلة قليلاً عن بعضها — يصبح:
- من الصعب تمييز البرومبتات المتشابهة عن بعضها
- من الصعب الرجوع لصورة قديمة ومعرفة البرومبت الذي أنتجها بالضبط
- لا توجد طريقة منظمة للبحث أو الفلترة أو المقارنة

## 2. الهدف من التطبيق
بناء تطبيق ويب شخصي (مستخدم واحد يسجّل دخول لحسابه) يعمل كأرشيف احترافي يربط كل صورة ببرومبتها وبياناتها، مع إمكانية تتبّع نسخ التعديل على نفس البرومبت، والبحث والمقارنة بسهولة.

## 3. المستخدم المستهدف
مستخدم واحد فقط (صاحب المشروع). لا حاجة لدعم عدة مستخدمين أو صلاحيات متعددة في هذه المرحلة، لكن يجب وجود تسجيل دخول بسيط (بريد/كلمة مرور) لحماية البيانات لأن التطبيق سيكون منشورًا على رابط عام.

## 4. الميزات التفصيلية

### 4.1 إضافة إدخال جديد (Entry)
**الوصف:** المستخدم يرفع صورة ويكتب/يلصق البرومبت المرتبط بها.

**الحقول المطلوبة عند الإضافة:**
- الصورة (رفع ملف — يدعم jpg, png, webp)
- البرومبت الإيجابي (Positive Prompt) — نص طويل
- البرومبت السلبي (Negative Prompt) — نص طويل، اختياري
- اسم النموذج المستخدم (مثال: Midjourney v6, SDXL, Flux) — حقل نصي حر أو قائمة منسدلة قابلة للتوسعة
- إعدادات إضافية اختيارية: Seed, Steps, CFG Scale, Sampler — حقول نصية اختيارية
- الوسوم (Tags) — يمكن إضافة أكثر من وسم، مع اقتراح وسوم موجودة مسبقًا أثناء الكتابة
- المجموعة/المشروع (Collection) — اختيار من قائمة أو إنشاء مجموعة جديدة
- ملاحظات شخصية (Notes) — نص حر اختياري
- **ربط بإدخال سابق كـ"نسخة معدّلة منه"** — حقل اختياري لاختيار إدخال موجود مسبقًا يُعتبر هذا الإدخال نسخة/تعديل عليه (انظر 4.4)

**معيار القبول:** بعد الحفظ، يظهر الإدخال فورًا في المعرض الرئيسي بدون الحاجة لتحديث الصفحة.

### 4.2 المعرض الرئيسي (Gallery)
- عرض جميع الإدخالات كشبكة صور (Grid) مع صورة مصغّرة (Thumbnail) لكل إدخال
- عند المرور على الصورة أو الضغط عليها، تظهر معاينة سريعة (أول سطرين من البرومبت + اسم النموذج)
- الضغط على الصورة يفتح صفحة/نافذة التفاصيل الكاملة (انظر 4.3)
- دعم التمرير اللانهائي أو الترقيم (Pagination) عند وجود عدد كبير من الإدخالات
- خيار لتغيير حجم الشبكة (عرض أكبر/أصغر للصور)

### 4.3 صفحة تفاصيل الإدخال
عند فتح إدخال معيّن، تُعرض:
- الصورة بالحجم الكامل
- البرومبت الإيجابي والسلبي كاملَين، مع **زر نسخ سريع** (Copy to Clipboard) لكل منهما
- كل البيانات الوصفية (النموذج، Seed، Steps، إلخ)
- الوسوم والمجموعة
- الملاحظات الشخصية
- **شجرة النسخ:** إن كان هذا الإدخال مرتبطًا بإدخالات أخرى (أصل أو نسخ فرعية منه)، تُعرض روابط لها
- أزرار: تعديل، حذف، تحديد كمفضلة (⭐)، مقارنة مع إدخال آخر

### 4.4 ربط ومقارنة النسخ (الميزة الأهم في المشروع)
**المشكلة التي تحلها:** عندما يعدّل المستخدم برومبتًا تعديلاً طفيفًا وينتج صورة جديدة، بدل أن يصبح إدخالاً منفصلاً غير مرتبط بالأصل، يمكن ربطه.

**المطلوب تنفيذه:**
- عند إضافة إدخال جديد، إمكانية اختيار إدخال موجود كـ"أصل" له (Parent)
- في صفحة التفاصيل، عرض "شجرة" أو قائمة بكل الإدخالات المرتبطة (الأصل + كل النسخ الفرعية منه)
- **صفحة/نافذة مقارنة الفروقات النصية (Diff View):** عند اختيار إدخالَين مرتبطَين، يعرض التطبيق البرومبتين جنبًا إلى جنب مع تمييز الكلمات المُضافة (بالأخضر مثلاً) والمحذوفة (بالأحمر) — يمكن استخدام مكتبة جاهزة لمقارنة النصوص (مثل diff أو jsdiff في JavaScript)

### 4.5 كشف التشابه التلقائي (اختياري لكن مطلوب إن أمكن)
عند كتابة برومبت جديد، إذا كان مشابهًا بنسبة عالية (مثلاً أكثر من 85%) لبرومبت موجود مسبقًا، يظهر تنبيه للمستخدم "يوجد برومبت مشابه، هل تريد ربطه به بدل إنشاء إدخال منفصل؟" مع رابط للإدخال المشابه.

### 4.6 البحث والفلترة
- شريط بحث نصي يبحث داخل نص البرومبت (الإيجابي والسلبي) وداخل الملاحظات
- فلاتر جانبية:
  - حسب المجموعة (Collection)
  - حسب الوسوم (يمكن اختيار أكثر من وسم)
  - حسب النموذج المستخدم
  - حسب المفضلة (⭐ فقط)
  - حسب نطاق التاريخ
- يمكن الجمع بين البحث النصي والفلاتر في نفس الوقت

### 4.7 المقارنة الجانبية (Compare View)
تحديد إدخالين أو أكثر (ليس بالضرورة مرتبطين كنسخ) وعرضهما جنبًا إلى جنب: الصورة + البرومبت + البيانات الوصفية، لتسهيل المقارنة اليدوية بين نتائج مختلفة.

### 4.8 المجموعات (Collections)
- إنشاء/تعديل/حذف مجموعات (مثال: "شخصيات"، "خلفيات"، "مشروع كذا")
- كل إدخال ينتمي لمجموعة واحدة (اختياري — يمكن ترك الإدخال بدون مجموعة)
- صفحة تعرض كل مجموعة وعدد الإدخالات فيها

### 4.9 الوسوم (Tags)
- وسوم حرة يُنشئها المستخدم بنفسه (وليست قائمة ثابتة)
- إدخال واحد يمكن أن يحمل أكثر من وسم
- عند الكتابة، يقترح التطبيق وسومًا موجودة مسبقًا لتفادي تكرار وسوم متشابهة بأسماء مختلفة (مثل "خلفية" و"خلفيات")

### 4.10 التصدير والاستيراد (نسخ احتياطي)
- زر "تصدير كل البيانات" ينزّل ملف JSON يحتوي كل البرومبتات والبيانات الوصفية (بدون الصور نفسها، فقط روابطها)
- إمكانية استيراد ملف JSON مشابه لاستعادة البيانات

### 4.11 تسجيل الدخول
- شاشة تسجيل دخول بسيطة (بريد إلكتروني + كلمة مرور) عبر خدمة المصادقة الجاهزة (موضحة في الملف التقني)
- لا حاجة لتسجيل مستخدمين جدد من الواجهة — حساب واحد فقط يُنشأ يدويًا من لوحة تحكم الخدمة

## 5. أولوية التنفيذ (مهم للمطوّر)
يُفضّل تنفيذ الميزات بهذا الترتيب لضمان وجود نسخة عاملة مبكرًا:

**المرحلة 1 (أساسية):** تسجيل دخول → إضافة إدخال → المعرض الرئيسي → صفحة التفاصيل
**المرحلة 2:** البحث والفلترة → الوسوم → المجموعات
**المرحلة 3:** ربط النسخ (Parent/Child) → صفحة مقارنة الفروقات النصية (Diff)
**المرحلة 4:** المقارنة الجانبية → كشف التشابه التلقائي → التصدير/الاستيراد

## 6. خارج نطاق المشروع الحالي (لا يُطلب تنفيذه)
- توليد الصور نفسه (التطبيق لا يولّد صورًا، فقط يؤرشف صورًا موجودة مسبقًا)
- دعم عدة مستخدمين أو مشاركة الإدخالات بين حسابات
- تطبيق جوال منفصل (المطلوب فقط تطبيق ويب متجاوب Responsive يعمل على الجوال عبر المتصفح)
