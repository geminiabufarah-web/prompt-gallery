# قائمة الحسابات والإعداد المطلوب

## الحسابات التي يجب إنشاؤها (كلها مجانية)

| # | الخدمة | الرابط | الغرض |
|---|---|---|---|
| 1 | Supabase | https://supabase.com | قاعدة البيانات + تسجيل الدخول |
| 2 | Cloudflare (لـ R2) | https://dash.cloudflare.com | تخزين الصور |
| 3 | Vercel أو Netlify | https://vercel.com أو https://netlify.com | استضافة الواجهة الأمامية |
| 4 | GitHub | https://github.com | استضافة الكود المصدري (مطلوب لربطه بـ Vercel/Netlify للنشر التلقائي) |

**ملاحظة:** يفضَّل أن ينشئ **صاحب المشروع** هذه الحسابات بنفسه (وليس المطوّر) للاحتفاظ بالملكية الكاملة على البيانات والمشروع، ثم يمنح المطوّر صلاحية وصول محدودة إن لزم الأمر.

---

## المتغيرات البيئية المطلوبة (Environment Variables)

يجب على المطوّر إنشاء ملف `.env.example` (بدون قيم فعلية، فقط أسماء المتغيرات) ضمن الكود المُسلَّم، يحتوي على:

```
# Supabase
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=

# Cloudflare R2
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=
R2_PUBLIC_URL=
```

**تنبيه أمني مهم:** المتغيرات التي تبدأ بـ `VITE_` تكون مرئية في كود المتصفح (Frontend) — لذلك يجب ألا تحتوي على أي مفتاح سري خاص بـ R2. مفاتيح R2 (Access Key / Secret Key) يجب أن تُستخدم فقط في طرف الخادم (Serverless Function) ولا تظهر أبدًا في كود الواجهة الأمامية.

## خطوات الإعداد الأولي (قبل أن يبدأ المطوّر بالكود)

1. إنشاء مشروع جديد في Supabase → الحصول على `SUPABASE_URL` و `ANON_KEY`
2. إنشاء الجداول في Supabase بحسب الملف `03-مخطط-قاعدة-البيانات.md` (يمكن للمطوّر تنفيذ ذلك عبر SQL Editor في لوحة Supabase)
3. تفعيل Row Level Security على كل الجداول
4. إنشاء مستخدم واحد يدويًا من قسم Authentication في Supabase (بريد + كلمة مرور صاحب المشروع)
5. إنشاء حاوية (Bucket) جديدة في Cloudflare R2
6. توليد Access Key و Secret Key من إعدادات R2
7. (اختياري لكن موصى به) ربط نطاق فرعي مجاني بالحاوية لتسهيل الوصول العام للصور
8. رفع الكود إلى مستودع GitHub جديد
9. ربط المستودع بـ Vercel أو Netlify للنشر
